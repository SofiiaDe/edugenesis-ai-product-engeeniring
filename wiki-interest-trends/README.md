# wiki-interest-trends — Agent Skill

Навичка для AI-агента, яка допомагає засновникам B2C-продуктів вирішувати, **які теми розвивати** та **якими мовами
запускатися**, на основі статистики переглядів Wikipedia (Wikimedia Pageviews API).

Агент (навіть на швидкій недорогій моделі, наприклад Claude Haiku 4.5) лише обирає параметри, запускає CLI,
перевіряє результати за чеклістом і пояснює їх. Уся робота з даними — у Java-коді навички.

## Що робить

| Крок          | Хто   | Що відбувається                                                                                                                            |
|---------------|-------|--------------------------------------------------------------------------------------------------------------------------------------------|
| Тема → статті | Java  | Wikidata: точна назва статті або пошук; назва статті в кожній мові; перенаправлення (redirects)                                            |
| Дані          | Java  | Місячні перегляди людей (`agent=user`) статті + загальний трафік мовного розділу; дисковий кеш                                             |
| Аналітика     | Java  | YoY (сирий і нормалізований), тренд Тейла-Сена, тест Манна-Кендалла, сплески (robust z), сезонність                                        |
| Довіра        | Java  | Явні перевірки: обсяг, значущість, послідовність, залежність від сплесків, raw vs normalized, історія статті → HIGH/MEDIUM/LOW з причинами |
| Ранжування    | Java  | Бал 0–100 з вагами користувача (`--weights volume=…, growth=…, confidence=…`)                                                                |
| Візуалізація  | Java  | `trend.png`, `growth.png` (Java2D), PDF на одну сторінку A4 (PDFBox)                                                                       |
| Висновки      | Агент | Формулювання простою мовою (готові речення в `summary.md`), нотатки для PDF, наступні кроки                                                |

## Встановлення та запуск

Потрібно: JDK 25+ та інтернет. Встановлений Maven не потрібен: запускачі завжди збирають через Maven Wrapper (скриптовий, без бінарних файлів), який закріплює Maven 3.9.16 і сам завантажує його при першій збірці.
Скомпільованих файлів у репозиторії немає: запускач сам збирає `target/wiki-interest-trends.jar` під час першого
запуску (~1 хв) і перезбирає після змін у коді. Збірка відтворювана (`project.build.outputTimestamp`): чиста копія дає
побайтово той самий jar.

Встановлення як навички Claude Code: скопіюйте директорію в `~/.claude/skills/` (або `.claude/skills/` проєкту).

### Команди для запуску

Запускайте з **кореня репозиторію** (папка, у якій лежить `wiki-interest-trends/`). Шляхи в `--out` / `--run`
відносні до поточної папки, тому результати з'являться в `wiki-trends-runs/…` (ця папка є в `.gitignore`).
Перший запуск збирає jar (~1 хв).

**Git Bash / Linux / macOS:**

```bash
cd <корінь-репозиторію>
bash wiki-interest-trends/scripts/wiki-trends analyze --topic "Intermittent fasting" --langs pl,cs --months 24 --out wiki-trends-runs/fasting --report uk
```

**PowerShell (Windows):**

```powershell
cd <корінь-репозиторію>
& .\wiki-interest-trends\scripts\wiki-trends.ps1 analyze --topic "Intermittent fasting" --langs pl,cs --months 24 --out wiki-trends-runs/fasting --report uk
```

**cmd.exe** (або PowerShell, якщо запуск `.ps1` заборонено політикою виконання):

```bat
cd <корінь-репозиторію>
wiki-interest-trends\scripts\wiki-trends.cmd analyze --topic "Intermittent fasting" --langs pl,cs --months 24 --out wiki-trends-runs/fasting --report uk
```

У PowerShell перед шляхом до `.cmd` додайте `.\`: `.\wiki-interest-trends\scripts\wiki-trends.cmd analyze ...`.

Запускати можна з будь-якої папки, якщо вказати повний шлях до скрипта: він сам знаходить свій jar, а результати
пишуться відносно поточної папки. Кожна тема — окрема папка (`--out`), у ній дані, графіки й `report.pdf`.
`--report uk|en` створює PDF у тому ж запуску; окрема команда `report --run <папка> --lang uk` перебудовує PDF з уже
зібраних даних (наприклад, іншою мовою). Без `--notes` звіт сам пише висновки з даних (напрям, довіра, прогалини в контенті, наступні кроки). Щоб додати власні висновки, передайте `--notes файл.md` (перший рядок `# Заголовок`, далі 5–8 пунктів; зразок — [examples/notes-example.md](examples/notes-example.md)). Агент у Claude Code пише такий файл сам.

### Приклад: тема українською, аналіз і PDF одним рядком (PowerShell)

Кешбек у польській, українській, румунській та англійській Вікіпедії за 3 роки; звіт українською відкривається одразу.
Запускайте з кореня репозиторію:

```powershell
& .\wiki-interest-trends\scripts\wiki-trends.ps1 analyze --topic "Кешбек" --search-lang uk --langs pl,uk,ro,en --months 36 --out wiki-trends-runs/cashback --report uk; Invoke-Item wiki-trends-runs\cashback\report.pdf
```

`--search-lang uk` потрібен, бо назва теми українською. Команди розділені `;` (у PowerShell 5.1 `&&` і `&` як роздільник не працюють).

### Параметри

Повний список у терміналі: `wiki-trends help` (PowerShell: `& .\wiki-interest-trends\scripts\wiki-trends.ps1 help`).
Усі опції з деталями, формати вихідних файлів і типові помилки — у [references/cli.md](references/cli.md).

**`analyze`** — зібрати дані й порахувати тренди:

| Параметр | За замовчуванням | Що робить | Приклад |
|---|---|---|---|
| `--topic` | — | Тема: назва статті або Wikidata id. Можна повторювати, щоб порівняти кілька тем | `--topic "Astronomy"`, `--topic Q5048719` |
| `--search-lang` | `en` | У якій Вікіпедії шукати назву з `--topic`. Потрібен для неанглійських назв | `--topic "Кешбек" --search-lang uk` |
| `--langs` | мова пошуку | Мовні розділи для аналізу (коди Вікіпедії) або `all` — 40 найбільших, де є стаття | `--langs uk,pl,ro,en` |
| `--months` | `36` | Довжина періоду в місяцях (3–130). Для порівняння рік до року — щонайменше 24 | `--months 24` |
| `--end` | останній повний місяць | Останній місяць періоду | `--end 2025-12` |
| `--out` | `wiki-trends-runs/<тема>_<мови>` | Папка для результатів | `--out wiki-trends-runs/cashback` |
| `--article` | — | Задати статтю вручну (`мова:Назва`, кілька через `\|`), разом із `--label` | `--article "pl:Moneyback" --label "Cashback"` |
| `--basis` | `normalized` | Зростання як частка від трафіку всієї Вікіпедії (`normalized`) чи в сирих переглядах (`raw`) | `--basis raw` |
| `--weights` | `volume=0.3,growth=0.5,confidence=0.2` | Ваги для балу: обсяг, зростання, довіра | `--weights volume=0.6,growth=0.3,confidence=0.1` |
| `--access` | `all-access` | Тип трафіку: `all-access`, `desktop`, `mobile-web`, `mobile-app` | `--access mobile-app` |
| `--max-langs` | `40` | Скільки розділів брати для `--langs all` | `--max-langs 60` |
| `--no-redirects` | вимкнено | Не додавати перегляди через перенаправлення | `--no-redirects` |
| `--question` | — | Питання користувача; показується в summary і як заголовок PDF | `--question "Чи росте інтерес до кешбеку?"` |
| `--report` | — | Одразу створити `report.pdf` у тій самій папці: `en` або `uk` (разом можна `--notes`, `--title`) | `--report uk` |
| `--chart-lang` | `en` | Мова підписів на PNG-графіках: `en` або `uk` | `--chart-lang uk` |
| `--spec` | — | Перезапустити збережені ряди з `spec.json` з іншими параметрами | `--spec wiki-trends-runs/cashback/spec.json --months 60` |
| `--offline` | вимкнено | Лише кешовані дані, без мережі | `--offline` |

**`report`** — PDF на одну сторінку:

| Параметр | За замовчуванням | Що робить |
|---|---|---|
| `--run` | — (обов'язковий) | Папка результатів `analyze` |
| `--lang` | `en` | Мова звіту й висновків: `en` або `uk` |
| `--notes` | висновки генеруються з даних | Власні висновки з файлу (`# Заголовок`, 5–8 пунктів) |
| `--title` | питання або «Інтерес до теми …» | Заголовок звіту |
| `--out` | `<run>/report.pdf` | Шлях до PDF |

**Інші команди:**

| Команда | Для чого | Приклад |
|---|---|---|
| `resolve` | Перевірити, на які статті відображається тема в кожній мові | `resolve --topic "Кешбек" --search-lang uk --langs pl,uk,ro,en` |
| `search` | Знайти статті в одній Вікіпедії, коли прямої статті немає | `search --lang ro --query "cashback"` |
| `cache` | Показати розмір кешу або очистити його (`--clear`) | `cache --clear` |

Ручна збірка й тести: `./mvnw package` (PowerShell: `.\mvnw.cmd package`), 14 юніт-тестів.

## Ключові рішення

- **Нормалізація за трафіком мовного розділу** (за замовчуванням). У 2024–2026 роках людський трафік Wikipedia
  впав у більшості мов (−16…−33% рік до року в перевірених розділах). Без нормалізації майже кожна тема виглядала б
  такою, що «падає». Сирі цифри теж показуються, розбіжність — окрема перевірка.
- **Правила довіри замість «відчуттів» моделі.** Модель не рахує статистику; вона переказує вердикт і причини.
  У `summary.md` є готові речення («STABLE: +2% в межах ±10%, не називайте це зростанням»), бо слабка модель
  схильна посилювати формулювання.
- **Перенаправлення.** Pageviews рахуються за запитаною назвою, тож перегляди через redirects додаються.
- **Кеш.** Завершені місяці не змінюються — кешуються назавжди. Повторні й уточнювальні запити майже
  не звертаються до мережі; `spec.json` дозволяє перезапустити ті самі ряди з іншим періодом/вагами.
- **Unicode-аргументи.** На Windows JVM декодує argv у ANSI (Cp1252) і видаляє кирилицю. Запускачі передають
  аргументи як base64 (UTF-8); для прямого запуску є `--option @file.txt`.
- **Ввічливість до API.** User-Agent за етикетом Wikimedia, глобальний rate limit (10 запитів/с), повтори з
  урахуванням `Retry-After`; збій однієї мови не зупиняє скан 40 мов.

## Перевірка

1. **Юніт-тести** (`AnalyzerTest`, `StatsTest`, 14 тестів) на синтетичних рядах: рівне зростання → GROWING/HIGH;
   плоский ряд → STABLE; один вірусний місяць → сплеск і LOW; падіння всієї Вікіпедії при плоскій темі →
   нормалізоване зростання; нова стаття → coverage fail; низький обсяг; сезонний пік у вересні; короткий ряд;
   вплив ваг на бал; Манн-Кендалл/Тейл-Сен/нормальний розподіл на відомих значеннях.
2. **Реальні дані** для всіх трьох прикладів завдання, скану `--langs all` (40 розділів за ~20 с, без HTTP 429),
   кириличних аргументів через bash і PowerShell, PDF (рендер у PNG і візуальна перевірка: одна сторінка,
   кирилиця, без обрізання).
3. **Відтворювана збірка**: копія без `target/`, `./mvnw package` → SHA-256 jar збігся з оригіналом.
4. **Повний сценарій на Claude Haiku 4.5**: окремі агенти Haiku отримували лише шлях до навички та запит
   користувача (приклади з завдання) і мали показати всі команди, які виконали. Перевіряв їхні відповіді за
   `evals/evals.json` і дивився створені файли (summary, PDF). Що знайшли ці прогони і що я виправив:
    - Haiku не зробив PDF на запит «підготуй звіт» → у SKILL.md тепер прямо сказано, що звіт = `report.pdf`, і є
      чекліст.
    - Haiku назвав STABLE (+2%) «зростаючим попитом» і підписував мовні розділи назвами країн → інструмент тепер
      друкує готові формулювання простою мовою для кожного ряду («мовний розділ, а не країна»).
    - −9,96% і −10,04% обидва показувались як «−10%», але мали різний вердикт → формулювання з одним знаком після коми.
    - Відсутня стаття в pl (інтервальне голодування) — Haiku коректно назвав це прогалиною в контенті й шукав
      замінник через `search`.

## Як розвивати далі

Ітеративно, від простого до складного; кожен крок перевіряти на `evals/` з дешевою моделлю.

1. **Автоматичні evals.** Скрипт, який проганяє `evals.json` через Haiku/безкоштовну модель OpenRouter і
   автоматично перевіряє очікування (є PDF, числа з відповіді є в `summary.md`, немає слова «зростає» для STABLE).
   Регресії в поведінці агента ловити так само, як юніт-тести.
2. **Кращі проксі тем.** Кластери статей через Wikidata (підкласи, «part of»), категорії та пов'язані статті;
   автоматичний
   підбір кандидатів, коли статті немає (як pl для інтервального голодування), з людським підтвердженням.
3. **Точніша статистика.** Модифікований Манн-Кендалл з урахуванням автокореляції (Hamed-Rao) або сезонний MK;
   bootstrap-інтервали для YoY; STL-декомпозиція; детекція точок зламу (коли почалося падіння).
4. **Більше контексту ринку.** Мова → країни (частка переглядів за країнами з Wikimedia per-country data),
   кількість мовців, купівельна спроможність; бал з поправкою на розмір аудиторії, а не лише розмір вікі.
5. **Великі обсяги даних.** Для сотень тем × мов: пакетні запити по днях/місяцях з дампів
   (`dumps.wikimedia.org/other/pageview_complete`) замість REST; локальне сховище (DuckDB/Parquet);
   інкрементальне оновлення лише нових місяців; паралельний скан з адаптивним rate limit.
6. **Порівняння в часі та моніторинг.** Збереження історії запусків, щомісячний звіт «що змінилося», алерти на
   різкі зміни інтересу.
7. **Звіти.** Шрифт-фолбек для CJK/арабської в PDF, багатосторінковий звіт для великих порівнянь, HTML-версія.
8. **Інші джерела для перевірки висновків.** Google Trends, дані магазинів застосунків, Reddit/YouTube — щоб
   відрізнити цікавість від попиту; вони підключаються як додаткові ряди в тій самій моделі перевірок.
